# Benchmark run guides

These guides describe the intended MINCER workloads, the upstream locations for separately acquiring their source/data, and how to invoke MINCER's experiment runner once a compatible workload directory and `run.sh` are available.

For first-time setup on the three Chameleon machines, follow the [node quick start](../nodes/quickstart.md).

**Status:** [CPU matrix multiplication](matrix-multiplication.md),
[XSBench OpenMP](xsbench.md#included-cpu-openmp-example), and
[LULESH OpenMP](lulesh.md#cpu-prepare-and-run) have been validated on
one Xeon Gold 6240R node; see the [CPU validation record](../nodes/cpu-validation.md).
[XSBench CUDA](xsbench.md), [LULESH CUDA](lulesh.md),
and [Gunrock CUDA](gunrock.md) have been tested on an RTX 6000; see the
[validation record](../nodes/nvidia-validation.md). XSBench HIP has been
validated on a dual-MI100 node, while AMD LULESH and Gunrock remain
unvalidated; see the
[AMD validation record](../nodes/amd-validation.md). Do not treat recorded
performance counters as expected values for a different node.

## Before running a guide

1. Provision a Linux Chameleon node appropriate for the selected CPU/GPU backend.
2. Install/configure Docker and the corresponding host GPU runtime/driver.
3. Build the applicable image from a root Dockerfile, or use an image already configured for the benchmark.
4. Use the included XSBench CPU/OpenMP or CUDA source, or download other
   benchmark source/data to a separate location; do not commit downloaded
   payloads.
5. Confirm the benchmark directory contains a working `run.sh` compatible with that source and node.
6. From the repository root, run:

   ```bash
   python3 mincer-package/run_experiment.py --path /absolute/path/to/workload
   ```

The runner expects `run.sh` inside the workload directory. It invokes that
script with Bash and saves captured output and system information under
`experiment_logs/`. Platform setup prepares images/dependencies; example
launchers build and run the workload. The runner's optional reference comparison
is textual, not a numerical-tolerance check. The included CPU examples perform
their own numerical checks even without a reference file.

## Known portability blockers in the local historical scripts

- `setup_cuda.sh` prepares the NVIDIA XSBench, LULESH, and Gunrock workflows.
  `setup_cpu.sh` prepares the shared CPU environment and pinned LULESH sources;
  AMD setup remains absent.
- Several old `run.sh` files mount fixed paths under `/home/cc/` and expect image names that differ between examples. Replace these paths/tags for the actual checkout and node.
- Some documented runs use PAPI-instrumented variants. Downloading an upstream project alone may not reproduce those modifications or expose the same PAPI events.
- The historical PyTorch KiTS19 workflow expects preprocessed HDF5 case files. The full dataset download command is given in its guide, but the conversion/subset-preparation procedure for the exact historical files is not included here.

Resolve and test these points on the Chameleon allocation before publishing measured results as reproducible.
